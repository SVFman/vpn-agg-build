# VPN Subscription Aggregator — оптимизированный пакет

Обновлённая версия проекта по итогам код-ревизии и второй ревизии с независимым
экспертом. Проверена юнит-тестами (98 проверок в `tests/`, запускаются без сети:
`python3 -m unittest discover -s tests`), e2e-сценариями и рабочими запусками
в GitHub Actions.

## Структура пакета

```
vpn-subscription-aggregator/
├── .github/workflows/update_subscriptions.yml   # единый workflow (заменяет три старых)
├── .github/workflows/mirror-sources.yml         # суточное зеркалирование gitverse
├── scripts/aggregate_subscription.py            # обновлённый скрипт
├── scripts/mirror_sources.py                    # терпеливый загрузчик зеркал
├── tests/                                       # юнит-тесты (unittest, без сети)
├── mirrors/                                     # стартовые зеркала (KvRuVPN, Zieng2_NowMeow)
├── subscription-sources.txt                     # два gitverse-URL заменены на file:mirrors/
├── README.md                                    # этот файл
└── alternative-three-workflows/                 # справительные копии СТАРЫХ workflow (в репо не нужны)
```

## Развёртывание (один коммит)

1. Заменить в репо `scripts/aggregate_subscription.py`, добавить `scripts/mirror_sources.py`.
2. Добавить каталог `mirrors/` с двумя стартовыми зеркалами.
3. Положить оба workflow: `update_subscriptions.yml` и `mirror-sources.yml`.
4. Заменить `subscription-sources.txt` (два gitverse-URL там заменены на `file:mirrors/...`).
5. **Удалить три старых workflow** (`update_igareck.yml`, `update_checked.yml`,
   `update_cepreu54.yml`). Это важно: у старого `cepreu54` своя concurrency-группа
   (`subscription-git-push`), поэтому при одновременном запуске с новым workflow
   возможна гонка git push (non-fast-forward) — `git-auto-commit-action` перед пушем
   не делает `git pull`.

Зеркала уже включены в пакет — первый запуск после коммита работает сразу,
дождаться суточного workflow не нужно.

## Что изменено в скрипте

- **Дедуп-ключ** учитывает транспорт (`net`/`type`) и параметры REALITY (`pbk`, `sid`,
  `flow`), регистр UUID нормализован — разные узлы на одном `host:port` больше не
  схлопываются, а полные дубли (отличающиеся только remark) по-прежнему убираются.
- **Пустой результат не затирает рабочую подписку**: сохранение прерывается, файлы
  остаются с прошлой (заведомо рабочей) версией, job краснеет.
- **Честные коды выхода**: нет файла источников или все источники режима недоступны —
  exit 1. Режимы независимы: авария одного не блокирует остальные; итоговый код — 1,
  если упал хотя бы один.
- **Замок домена удерживается только на троттлинг** — один медленный/падающий источник
  больше не блокирует остальные потоки того же домена; реестр замков потокобезопасен.
- Ретраи включают код 500; поддержан urlsafe-base64 (vmess); усечения
  `MAX_SOURCE_BYTES` и `MAX_LINES` логируются; plain-файл завершается `\n`.
- Удалён мёртвый код (`last_error` и лишние параметры); `run_dedup_group`/`run_checked`
  объединены в `run_group(..., dedup=...)`.
- **Пауза для gitverse.ru увеличена до 4 с**: в прод-запуске №1 три из четырёх
  gitverse-источников получили 429 даже с ретраями при паузе 1.5 с.
- **Локальные зеркала**: строка `file:путь/от/корня` в `subscription-sources.txt`
  читается с диска — без сети, ретраев и троттлинга.

## Вторая ревизия (независимый эксперт, ноябрь 2026)

Все 11 предложений проверены против кода и живыми замерами источников;
согласованные изменения:

1. **Потолок Retry-After 60 с + общий дедлайн сбора 180 с** от старта процесса —
   один на все источники всех режимов (первый ограничитель), per-source потолок
   180 с — второй. Злой заголовок `Retry-After: 600` больше не может съесть job:
   пауза = min(RA + jitter, 60 с, остаток дедлайна). Попытка не начинается, если
   на неё не остаётся полного таймаута запроса; следующая «волна» источников
   свежего бюджета не получает — при массовом сбое сборка падает быстро сама
   (exit 1, прежние файлы нетронуты), а не убивается по `timeout-minutes`.
   Переопределение: переменная окружения `FETCH_DEADLINE_SECS`.
2. **Дедлайн зеркалирования 17 минут** на весь прогон (`MIRROR_DEADLINE_SECS`)
   при `timeout-minutes: 25` в `mirror-sources.yml`. Прежде два источника по 8
   попыток с паузами 90–615 с могли выйти за 20-минутный таймаут даже без злого
   Retry-After. Семантика exit 1 прежняя: только если зеркал нет вовсе.
3. **Режим checked собирается с дедупликацией** (`dedup=True`): на живом замере
   143 строки сжимались до 92 уникальных.
4. **Единая проверка адреса для всех протоколов**: trojan/hysteria2/hy2/ss/tuic
   теперь тоже проверяются `is_safe_address` (для ss декодируется legacy-base64,
   проверка выполняется до дедупа, добавлен wireguard). Плюс отсечение
   `localhost`, `*.local`, `*.localhost`. Нераспознанный адрес строку не
   отбрасывает (проверяем только уверенно распознанное).
5. **Битые vless отбрасываются по сырым query-параметрам** (суженная редакция):
   невалидный UUID; reality без `pbk`; reality без `sni`; tls без любого
   источника SNI (sni/peer/host одновременно). Проверка по сырым параметрам, а
   не по распарсенному dict — иначе fallback `sni` из host маскировал бы дефект.
   Счётчики по категориям — в логе и в сводке. Для vmess проверка UUID не
   добавлялась (сверх согласованного объёма).
6. **Новые подписки `igareck_xhttp.txt` и `cepreu54_xhttp.txt`** (+ их
   `_base64`-твины): только строки с транспортом xhttp/grpc; `splithttp`
   считается синонимом xhttp. Пустой результат файл не затирает и не создаёт —
   WARN в лог. В workflow покрываются автоматически (`file_pattern:
   subscription/*.txt`). Ориентир по объёму (живой замер): igareck ~188 из
   ~1296 строк (~15%), cepreu54 ~134 (~26%).
7. **Защита от деградации**: если результат группы меньше 50% строк прежнего
   plain-файла (файл от 20 строк), запись отменяется, прежние файлы остаются,
   job краснеет — коммит не выполняется (без `if: always()` у шага коммита).
   Сравнение — после дедупа и обрезки по `MAX_LINES`, до записи. Действует
   только для трёх главных выходов (igareck/cepreu54/checked), `_xhttp` не
   защищаются. Ручной обход: `workflow_dispatch` с `allow_shrink = true`
   (CLI: `--allow-shrink`) — для закономерных сокращений, когда источник
   удалён навсегда; автоматически флаг не включается.
8. **Атомарная запись всех выходов**: сначала оба `.tmp` (plain и base64),
   затем два `os.replace` подряд — окно рассинхрона пары минимально, обрыв не
   оставит битый или полупустой файл.
9. **Сводка по источникам в `$GITHUB_STEP_SUMMARY`**: markdown-таблица на 7
   колонок (строк загружено / отклонено с деталями / дубли внутри источника /
   перекрытые другими источниками / вклад в файл / статус), источники с 0 строк
   помечаются, ошибки — строкой ERR. Парсинг перенесён на стадию загрузки,
   порядок источников детерминированный (дедуп-победитель — первый по
   `subscription-sources.txt`, а не случайный поток). Отдельный счётчик
   `tcp/raw`: строки с `security=reality` (блокируемый ТСПУ класс) и прочие
   tcp/raw — только счётчик, без фильтрации из файлов.
10. **`inputs.mode` передаётся через env**, а не интерполяцией в shell —
    защита от инъекции; мусор отсекается `choices` argparse.

Не менялись: `subscription-sources.txt`, имена и формат существующих файлов,
cron, concurrency-группа `subscription-commit`.

## Что в workflow

- Один запуск (`--mode all`, по умолчанию) собирает все три подписки **одним коммитом**.
- Cron `20 */3 * * *` — каждые 3 часа. Раньше igareck обновлялся ежечасно; если нужна
  частота чаще — замените на `20 * * * *`.
- `concurrency: subscription-commit` + `cancel-in-progress: false` — пуш никогда не
  пересекается сам с собой.
- `timeout-minutes: 5` — зависший запуск не съедает минуты Actions; общий
  дедлайн сбора (180 с) даже при массовом сбое источников завершает сборку
  штатным `exit 1` раньше таймаута.
- Ручной запуск поддерживает выбор режима (trusted / cepreu54 / checked / all)
  и флаг `allow_shrink` для обхода защиты от деградации (п. 7 выше); оба входа
  передаются через env — защита от инъекции.
- `mirror-sources.yml` — отдельный workflow: раз в сутки терпеливо обновляет
  зеркала gitverse под дедлайном 17 минут (`timeout-minutes: 25`) и коммитит их;
  одна concurrency-группа со сборкой — пуш никогда не пересекается.

## Зеркалирование gitverse (решение проблемы 429)

gitverse.ru лимитирует запросы с IP раннеров GitHub Actions, а IP общие — лимит
бывает исчерпан ещё до старта прогона (первый же запрос получает 429), ретрями
это не лечится. Поэтому два проблемных списка выведены из сетевой части сборки:

- **Mirror GitVerse Sources** раз в сутки (04:40 UTC) скачивает KvRuVPN и
  Zieng2_NowMeow с терпеливыми паузами под общим дедлайном прогона 17 минут
  (Retry-After уважается) и коммитит их в `mirrors/`;
- контент сохраняется только если в нём есть строки конфигов (HTML-страница
  ошибки не пройдёт), запись атомарная; при неудаче остаётся прежняя
  (последняя удачная) версия; job краснеет, только если зеркал нет вовсе;
- `subscription-sources.txt` ссылается на них как `file:mirrors/...` — сборка
  читает их с диска мгновенно и к gitverse больше не обращается;
- RosTun и TG-WLTGFF остались прямыми — они проходят с паузой 4 с. Если начнут
  падать: добавить URL в TARGETS в `mirror_sources.py` и заменить строку в
  `subscription-sources.txt` на `file:mirrors/Имя.txt`.

Бонус: KvRuVPN (~930 конфигов) раньше вообще не попадал в подписку (стабильный
429) — после первого запуска ждите заметный рост igareck.

## Про «1 warning» в аннотациях запуска

Чаще всего это `Nothing to commit` от `git-auto-commit-action`: контент подписок не
изменился с прошлого запуска (источники отдают то же самое). Это не ошибка — шаг
пуша просто пропускается. Точный текст виден при раскрытии аннотации в UI Actions.
