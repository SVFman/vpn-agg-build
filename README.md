# VPN Aggregator (личное использование)

Простое Android-приложение (Kotlin, без Compose), которое:

1. По кнопке «Обновить и собрать список» параллельно опрашивает 31 зафиксированный
   источник (GitHub/raw.githubusercontent.com + gitverse.ru) из `Sources.kt`.
2. Собирает **все** полученные строки в один общий список (как и требовалось —
   сначала объединение, потом очистка).
3. Удаляет точные дубликаты (оставляет первое вхождение каждой уникальной строки).
4. Показывает результат в приложении: сколько всего собрано, сколько после
   удаления дублей, какие источники не ответили и почему.
5. Формирует подписку в формате, который понимает v2rayNG:
   - обычный текстовый файл `aggregated.txt` (построчно vless/vmess);
   - `aggregated_base64.txt` — то же самое, целиком закодированное в Base64
     (классический формат, который v2rayNG ожидает по ссылке подписки).
6. Даёт скопировать base64-подписку в буфер обмена или сохранить оба файла
   (`Context.getExternalFilesDir()/output/`) и сразу открыть системное меню
   «Поделиться» — например, чтобы отправить файл на свой будущий сервер подписки.

## Важные нюансы

- **Не все ссылки — списки серверов.** Часть URL в `Sources.kt`
  (`WHITE-CIDR-RU-*.txt`, `TG-@WLTGFF.txt`, `README.md` и т.п.) — это
  whitelist-ы доменов/IP для роутинга, а не конфиги vless/vmess. Для них
  агрегатор ожидаемо не найдёт ни одной строки — это не баг.
- **Дедупликация — по точному совпадению строки.** Если один и тот же сервер
  встречается в разных источниках с разным `#remark` (именем) в конце ссылки,
  такие записи **не** считаются дубликатами (это разные строки). Если нужно
  дедуплицировать именно по хосту/UUID без учёта имени — скажите, это
  отдельная, более сложная логика парсинга.
- **Часть источников отдают не построчный список, а один base64-блок**
  (как `All_Configs_base64_Sub.txt`). Это обработано: если в сыром ответе
  не нашлось строк `vless://`/`vmess://` напрямую, агрегатор пробует
  раскодировать весь ответ как base64 и ищет конфиги уже там.
- Приложение **не является VPN-клиентом** — оно не устанавливает VPN-туннель
  само, только готовит список/подписку для импорта в v2rayNG, как вы и просили.
- Собрано под личное использование: минимальная обфускация/подпись не
  настраивались, минимизация (`minifyEnabled`) выключена.

## Как собрать

Нужен Android Studio (Koala/Ladybug или новее) с установленным JDK 17.

1. Откройте папку `vpn-aggregator/` в Android Studio как проект (File → Open).
2. Дождитесь синхронизации Gradle (первая синхронизация скачает зависимости —
   нужен интернет).
3. Соберите APK: **Build → Build Bundle(s)/APK(s) → Build APK(s)**,
   либо из командной строки в корне проекта:

   ```bash
   ./gradlew assembleDebug
   ```

   Готовый файл появится в `app/build/outputs/apk/debug/app-debug.apk`.
4. Установите APK на телефон (нужно разрешить установку из неизвестных
   источников, т.к. приложение не из Google Play).

Если версии Android Gradle Plugin (8.6.0) или Kotlin (2.0.21) конфликтуют
с версией вашего Android Studio — Android Studio сам предложит обновить
их при открытии проекта, можно соглашаться.

## Дальнейшие шаги (на будущее, не реализовано в этой версии)

- Автоматическая выгрузка `aggregated_base64.txt` на ваш сервер подписки
  по HTTP(S) вместо ручного «Поделиться» — для этого понадобится адрес
  и метод (PUT/POST/SFTP/что угодно) вашего сервера.
- Health-check серверов (TCP-коннект) перед показом — вы указали, что
  пока не нужно, но логика в `Aggregator.kt` расширяется под это без
  переписывания остальной части приложения.
